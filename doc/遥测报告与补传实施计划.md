# 遥测报告与补传 Implementation Plan

**Goal:** 将 PLC 子设备采样接入报告策略、持久化 Outbox 和 MQTT data/dataAck，提供独立去重接收端。

**Architecture:** ReportEngine 只生成按版本隔离的候选批次；持久写入成功才推进死区基准。独立 telemetry.db 由专用 StoreWorker 拥有，已持久批次只在有效 STORED 后删除。MqttConfigService 复用原连接，独立有界发送循环不阻塞配置接收。接收端以 SQLite 事务去重，提交后才发送 STORED。

**Spec:** 初始技术设计第 7 节；IoT采集执行设计第 6–9 节。按已授权的后续阶段直接在当前工作区实施。

## 约束

- 支持 cyclic/change/change_or_cyclic，死区严格大于，质量变化绕过死区；以成功写入 Outbox 的值为基准。
- 一个批次一个 configVersion，最多 500 点且 128 KiB；保留原采样时刻。配置改变后新缓存从 UNKNOWN 开始，旧持久批次不改写。
- Outbox 默认最多 10000 条、64 MiB payload；入队满拒绝新批次并计数，7 天过期进入有界死信。死信默认保留 128 条，修剪累计计数。
- 最多 8 批在途，应用 ACK 等待 30 秒，重试间隔上限 60 秒；新数据/重试按 1:1 选择。PUBACK 不删除批次。
- 接收端是独立联调工具：持久版本快照和去重收据，未知版本可补充历史快照后重试；同身份不同内容拒绝。
- 不改 Hub；本轮不做批量 Modbus 读取或心跳。生产接收端容量、归档与告警仍为后续工作。
