# 闭环联调测试方案

日期：2026-09-17  
范围：PLCnext-iot Agent 0.2.0，对本地匿名 MQTT 与 PLCnext-mock-device 做端到端验收。  
本文件只规定环境、用例和判定；实测过程与结论见同目录《闭环联调测试报告》。

## 1. 测试目标

验证一条完整链路：

```text
配置端 --MQTT config/set--> Agent --采集--> mock 子设备
       <--config/ack------      --data/heartbeat/device/status--> 接收端
                            <--data/ack=STORED-------------------
```

覆盖：首次下发、配置修改、四类子设备采集、设备状态、下级设备掉线恢复、停止采集、非法配置不影响旧版本。

## 2. 环境约定

| 项目 | 约定 |
|---|---|
| MQTT | `127.0.0.1:1883`，匿名、无 TLS、无账号密码。端口空闲时由测试脚本启动可停可开的 Mosquitto；已有匿名 Broker 则直接使用 |
| 模拟器 | `D:\work\code\PLCnext-mock-device`，独立临时数据库，不改模拟器已有 `data/` |
| 模拟器 Web | `127.0.0.1:18080`（避开 8080） |
| Modbus TCP | `127.0.0.1:11502` |
| OPC UA | `opc.tcp://127.0.0.1:14840/iot-simulator/`，NoSecurity、匿名 |
| Agent | `gatewayId=PLC-01`，`--driver all`，临时 `agent.db` / `telemetry.db` |
| 接收端 | 独立进程订阅 `data`，校验后回 `data/ack=STORED` |

1883 空闲时，脚本用 Docker 启动可 stop/start 的匿名 Mosquitto（便于 T23）。1883 已有匿名 Broker 则直接使用，T23 跳过。Agent `tls=false`，无账号密码。

## 3. 模拟子设备

四个下级设备，点值互不相同：

| Agent deviceId | 协议 | 模拟器身份 | 点位 | 类型 | 期望量程 / 初值 |
|---|---|---|---|---|---|
| meter-A | Modbus TCP unit 1 | `meter-A` | voltage，holding 0 | uint16 | 220–240，初值 230 |
| meter-A | 同上 | 同上 | current，holding 2 | float32 | 1.0–10.0，初值 5.0 |
| meter-B | Modbus TCP unit 2 | `meter-B` | pressure，input 0 | float32 | 0–100，初值 12.5 |
| meter-B | 同上 | 同上 | running，coil 0 | bool | 恒为 true |
| tank-A | OPC UA | `tank-A` | level，`ns=2;s=tank-A.level` | float32 | 0–5，初值 2.5 |
| tank-B | OPC UA | `tank-B` | temperature，`ns=2;s=tank-B.temperature` | float32 | 18–35，初值 20.0 |
| tank-B | 同上 | 同上 | alarm，`ns=2;s=tank-B.alarm` | bool | 恒为 false |

Agent 侧 `scale=1`、`offset=0`，`reportMode=cyclic`，`pollIntervalMs=1000`。meter-A 的 voltage 在修改用例中改为 `scale=0.1`，期望工程值约为 22.0–24.0。

## 4. 用例清单

| 编号 | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| T01 | MQTT 就绪 | 连接本机 1883 匿名明文 Broker | CONNECT Success，无 TLS、无账号 |
| T02 | 模拟器就绪 | 启动 mock，写入四台设备 | Web `/api/v1/status` 正常；Modbus/OPC UA 端口监听 |
| T03 | Agent 启动 | 启动 Agent + 接收端 | 收到 `status` online；发出 `config/get` |
| T04 | 首次下发 | retained `config/set` v10，四台设备全开 | `config/ack` status=APPLIED，activeConfigVersion=10 |
| T05 | 数据采集 | 等待各点 GOOD 样本 | 7 个点均出现 GOOD；meter-A.voltage∈[220,240]；tank-B.alarm=false；各设备点值可区分 |
| T06 | 设备状态 | 观察 `device/status` 与 heartbeat | 四台均为 ONLINE；heartbeat 含 4 设备、点数 total≥7 |
| T07 | 遥测确认 | 接收端入库并 ACK | 至少一批 `data/ack=STORED`；Outbox 可被确认删除 |
| T08 | 修改配置 | v11：voltage scale=0.1，tank-A 周期改为 2000ms | APPLIED v11；随后 voltage∈[22.0,24.0] |
| T09 | 非法配置 | 下发 v11 同版不同内容，或 protocol 混用字段 | REJECTED；活动版本仍为 11；采集不中断 |
| T10 | Modbus 掉线 | 模拟器关闭 Modbus 适配器 | meter-A/B 变为 OFFLINE 或点质量 BAD_CONNECTION/BAD_TIMEOUT；tank 仍 ONLINE |
| T11 | Modbus 恢复 | 重新打开 Modbus 适配器 | meter-A/B 恢复 ONLINE，再出现 GOOD |
| T12 | OPC UA 掉线 | 关闭 OPC UA 适配器 | tank-A/B OFFLINE 或 BAD_CONNECTION；meter 仍 ONLINE |
| T13 | OPC UA 恢复 | 重新打开 OPC UA 适配器 | tank-A/B 恢复 ONLINE，再出现 GOOD |
| T14 | 停用单台设备 | v12：tank-B enabled=false | APPLIED；tank-B=DISABLED；其余 ONLINE 且继续出数 |
| T15 | 停止全部采集 | v13：config.enabled=false | APPLIED；四台 DISABLED；不再出现新的 GOOD 采集（心跳点数 total=0） |
| T16 | 重新采集 | v14：恢复 v10 内容（更高版本） | APPLIED v14；四台回到 ONLINE，采集恢复 |
| T17 | 清空子设备 | v15：devices=[] | APPLIED；无采集任务；心跳无设备或全 DISABLED |

补充用例（与 T01–T17 同一脚本连续执行）：

| 编号 | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| T18 | 同版本重复下发 | 再发 v14 相同内容 | APPLIED，活动版本仍为 14 |
| T19 | 旧版本下发 | 再发 v10 | REJECTED / STALE_VERSION，活动版本不倒退 |
| T20 | 离线仍 APPLIED | 关闭 Modbus 后下发更高版本 | APPLIED；OPC UA 继续出数 |
| T21 | 单点非法地址 | meter-A 增加未映射寄存器 | APPLIED；voltage/pressure 仍 GOOD |
| T22 | change 上报 | 全部点改为 reportMode=change | APPLIED 后仍能收到 GOOD |
| T23 | Broker 短暂断开 | 停止再启动测试用 Mosquitto | 恢复后 status online、电压继续 GOOD；测试自管 Broker 时执行 |
| T24 | 停 ACK 补传 | 测试端暂停 STORED 再恢复 | 暂停期间 stored 不增，恢复后继续 STORED |
| T25 | Agent 重启 | 停进程再拉起 | 无需新下发即可恢复采集 |
| T26 | 只停一台设备 | meter-B 指向无效端口 | meter-B 离线，meter-A 仍 GOOD |
| T27 | 错误 NodeId | tank-A 增加不存在节点 | ghost 坏质量，level 仍 GOOD |
| T28 | OPC UA 缺密码 | username + 不存在的 passwordEnv | APPLIED；tank-A 异常，meter 继续 |
| T29 | 混合周期 | 500/1000/2000/5000 ms | 全部点 GOOD |
| T30 | retained 启动 | 与 T25 同一次重启观察 | 本地库/retained 恢复采集 |

任一条失败不阻断后续可独立执行的用例；依赖前置版本的用例在前置失败时记为 BLOCKED。T23 在使用本机共享 1883 时记 SKIPPED。

## 5. 执行方式

在项目根目录、已安装 `requirements-runtime.txt` 的环境中：

```powershell
./.venv/Scripts/python.exe -m tools.closed_loop_test --mock-project D:/work/code/PLCnext-mock-device --mock-python .local/mock-venv/Scripts/python.exe
```

脚本自动：连接本机 1883、拉起模拟器、导入四台设备、启动 Agent/接收端、按上表执行、写出结果 JSON 和 Markdown 报告。结束后关闭模拟器子进程。不改模拟器原数据库，不连 Hub。不另起 Mosquitto。

需要本机 1883 已在监听且允许匿名。模拟器端口 18080、11502、14840 须空闲。

## 6. 记录要求

每条用例记录：编号、名称、开始/结束时间、结果（PASS/FAIL/BLOCKED）、期望、实际摘要、证据（ACK、质量、状态、messageId/configVersion）、失败时的日志摘录。

全部跑完后统计通过率，并列出问题（复现步骤、影响、是否阻塞闭环）。

## 7. 本轮范围与未覆盖

T01–T17 只验收**模拟器 + 匿名 MQTT + 单进程 Agent** 的功能闭环。下面条目属于后续测试方案，不计入本轮 17 条通过率。

### 7.1 已纳入脚本的补充用例

T18–T30 已写入 `tools.closed_loop_test`，与 T01–T17 一次跑完。T23 仅在脚本自己拉起的 1883 Mosquitto 上执行（可 stop/start）；外部占用 1883 时 SKIPPED。

### 7.2 单独成套的测试方案（本轮未做）

| 方案 | 对象 | 关键验收 |
|---|---|---|
| 配置事务与崩溃恢复 | 杀进程于 PREPARED / 切换中 / ACK 前 | 活动版本符合持久化边界 |
| MQTT 安全 | TLS、用户名、ACL、超大包、跨网关伪造 | 拒绝错误身份和过期证书 |
| 遥测可靠性 | ACK 丢失、重复 STORED、7 天过期、队列满 | 不重复入库、丢弃可见 |
| 初始化页 / App | 8080 首次设置、改 Broker、重启恢复 | PLC ID 不可改，采集自动起来 |
| 镜像与 WBM | AMD64 容器、2152/vPLC `.app` | 安装、持久卷、升级保留库 |
| 真机与长稳 | AXC F 2152 / vPLC，24h/72h/7d | CPU/RSS/磁盘、采样延迟、PLC 周期影响 |
| Hub 对接 | 子设备页汇总下发 | 点值回到 Hub，无重复直采 |

现有 `unittest`、`mqtt_smoke`、`telemetry_smoke`、`provisioning_smoke` 覆盖了其中一部分单元/隔离场景，**不能替代**上表的端到端条目。
