# 执行协调器与启动生命周期

本阶段在 PLC 本地连接配置存储与子设备执行器。配置仍以子设备为编辑单元，按 PLC 汇总下发；没有新增网关设备层级，也没有修改 Hub。

## 运行状态与事务

`AgentLifecycle` 拥有有界队列、单线程 `StoreWorker` 和 `DeviceRuntime`。启动按 NEW → STARTING 读取已提交配置，成功恢复执行器后进入 RUNNING（启用配置）或 DISABLED（停用配置）；没有配置进入 WAITING_CONFIG。空的启用配置也可以处于 RUNNING，不代表连接了设备。

配置请求串行执行：持久化 prepare → 构造执行器 → activate → 数据库 commit → 同步 publish → APPLIED。切换期间状态为 APPLYING。只有任务切换及提交均成功才返回本地 APPLIED；已提交配置的重发也要求本实例已恢复对应运行版本。

修改一个子设备只切换受影响的任务，删除或停用子设备会停止其任务。名称、单位、上报参数变化不重启采集执行器；消费者从已发布快照读取这些参数。连接、启用点位、采样周期、数据类型、缩放和地址变化会重建任务。

启动部分成功、超时或提交失败时，停止候选任务并恢复旧任务。数据库 commit 报错后重新读取活动指针：已提交新版本则继续发布，仍为旧版本才回滚。无法确认提交结果时进入 FAILED，停止受理并尝试停止所有任务，`active_config_version` 为 None，避免猜测持久化版本。恢复失败同样进入 FAILED，不伪报运行成功。

`ApplyResult(status, active_config_version, code, issues)` 是本地接口。后续 [MQTT 配置服务](MQTT配置闭环说明.md) 已实现协议错误码映射及 ACK；None 和本地诊断码不能直接复制到线上契约。APPLIED 表示本地执行器已建立，不表示远端设备在线。

## 取消、关闭和线程所有权

`submit` 只接收 bytes；校验报文上限并通过有界队列限制积压，满队列立即拒绝。已经入队的请求不会因为调用方取消等待而被中途撤销。关闭立即拒绝新请求，拒绝未开始的排队请求，等待在途事务结束，再停止执行器并关闭数据库。

`start` 每个实例只允许一次，`close` 幂等；等待启动或关闭的调用者取消时仍执行资源清理。需要重新启动时创建新实例，从已提交配置恢复。

SQLite 的创建、调用、解析和关闭都在同一个专用线程完成。数据库线程任务一旦开始，调用者取消不会强制中止该任务；必须等待其结果，避免留下未知的提交窗口。

执行器必须配合取消：`start`/`stop` 是异步方法，`stop` 幂等，旧执行器停止后允许重新启动，factory 构造阶段不能获取连接或启动后台任务。`operationTimeoutSeconds` 限制切换、恢复及逐个停止的等待，不是整个关闭过程的硬截止时间。不响应取消的驱动可能超出超时；清理失败时状态保持 FAILED，部署监管进程需要终止并重启 Agent。相关语义见 [Python asyncio 文档](https://docs.python.org/3.12/library/asyncio-task.html#asyncio.wait_for)。

## 采样发布边界

`DeviceRuntime.sample_context(device_id, runner)` 在所属事件循环调用，返回不可变的版本和子设备配置，未获得发布资格的执行器返回 None。候选执行器在 commit/publish 前不能发布；替换后的旧实例不能发布迟到结果。没有重启的实例会读取到新快照。

Modbus 与 OPC UA 执行器在采样时捕获 context，入队前再次检查实例资格与配置版本；候选或已被替换的执行器结果丢弃，不能用新版本重新标记旧采样。遥测队列与 MQTT 发送见 [遥测报告与补传说明](遥测报告与补传说明.md)。名称、单位和报告参数变化不重建执行器；连接、协议地址、启用点、周期、类型和缩放变化会重建。OPC UA 的 NodeId 包含在执行器身份中。

## 本地入口

Bootstrap 示例为 `deploy/bootstrap.example.json`，严格要求 gatewayId、dataDirectory、operationTimeoutSeconds、queueCapacity 四个字段，拒绝重复键和未知字段。数据目录相对 Bootstrap 文件解析。超时范围为 (0, 300] 秒，队列容量为 1–16，配置报文上限为 2 MiB。

在仓库根目录执行：

```powershell
./.venv/Scripts/python.exe -m tools.agent --bootstrap deploy/bootstrap.example.json --config contracts/examples/valid/config-empty.json --run-seconds 0
```

示例将状态保存在 `.local/agent/agent.db`。再次启动会恢复已提交配置。`--config` 可重复指定并顺序应用；省略它只恢复已有配置。省略 `--run-seconds` 持续运行，SIGINT/SIGTERM 触发有序关闭。输出 started/config_result/stopped JSON 事件；退出码 0 表示正常，1 表示应用或运行失败，2 表示启动参数或输入错误。

默认 `DeviceRuntime()` 没有协议驱动，空配置和停用配置可应用；存在启用采集点时拒绝为 UNSUPPORTED_DRIVER。`--driver modbus-tcp`、`--driver opcua` 或 `--driver all` 按协议注入只读执行器；容器和 systemd 使用 `all`。见 [Modbus 模拟采集说明](Modbus模拟采集说明.md) 和 [OPC UA 采集说明](OPC UA采集说明.md)。

## 验证与后续

测试覆盖重启恢复、任务复用、局部启动失败、提交失败及提交结果丢失、恢复失败、超时、调用方取消、有界队列、有序关闭、发布资格和 SQLite 线程归属。CLI 子进程使用临时目录验证空配置应用、重启恢复和无驱动拒绝，不触碰现场状态库。

Windows 开发环境的测试不能替代 Linux 信号处理、PLC 硬件、掉电及长期运行验证。源码目录、Linux 发布包、容器镜像和未签名 WBM 开发包均已提供。Modbus TCP、OPC UA、MQTT 配置、报告策略和遥测补传已在模拟环境联调；Hub 对接和 PLC 真机验收尚未完成。
