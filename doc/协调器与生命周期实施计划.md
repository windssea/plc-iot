# 执行协调器与启动生命周期 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 启动恢复真实执行状态，串行完成配置切换/持久提交/失败恢复，提供可运行的本地生命周期入口。

**Architecture:** AgentLifecycle 拥有有界请求队列、独立数据库工作线程和 DeviceRuntime。RuntimeTransition 负责受影响子设备的 activate/rollback；持久化提交后以同步无 I/O 的 publish 更新运行版本。默认无驱动时拒绝启用的采集设备，空配置和停用配置可完整执行。

**Tech Stack:** Python 3.12 asyncio、ThreadPoolExecutor(max_workers=1)、现有 ConfigStore、unittest.IsolatedAsyncioTestCase。

**Spec:** `doc/初始技术设计.md` 第 7 节；`doc/IoT采集执行设计.md` 第 6/8 节；`doc/配置持久化说明.md`。

## Global Constraints

- 不连接 MQTT、Modbus、Hub；仅通过明确注入的设备执行器建立真实 start/stop 边界。
- APPLIED 只能在运行切换和数据库提交均成功后返回。
- 未变化设备不重启，停用不保留活动执行器；失败必须恢复旧配置，恢复失败进入 FAILED 并停止受理。
- 所有 SQLite 操作在同一专用线程；外部等待取消不能截断提交。
- 配置队列有界；关闭拒绝新请求、拒绝尚未开始的排队请求、完成在途事务，再停止执行层并关闭存储。
- 同一生命周期实例只启动一次。失败重启使用新实例，恢复源为已提交数据库。
