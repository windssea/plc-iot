# 配置核心与 SQLite 持久化

本阶段实现配置存储边界：验证、准备、提交、失败以及进程重启恢复。它不连接现场设备，也不发送 MQTT ACK。配置归属与协议保持不变：子设备配置汇总到所属 PLC。

## 1. 当前代码

- `src/plcnext_iot/contracts.py`：从阶段 A 工具移入的唯一契约校验器。
- `src/plcnext_iot/config/models.py`：不可变 PLC/Device/Point/Connection/Report 模型。
- `src/plcnext_iot/config/store.py`：候选和活动版本持久化。
- `src/plcnext_iot/config/locking.py`：数据库单进程所有权锁。
- `tools/config_demo.py`：临时目录中的持久化演示。
- `tools/contract_validation.py`：旧工具兼容入口，继续复用核心校验器。

Schema 位于仓库 `contracts/v1`，发布包、容器镜像和 WBM 开发包都会带上契约资源。本地开发仍可按源码目录运行。

## 2. 模型与内容比较

`ConfigSnapshot.parse(payload, gateway_id)` 先完成阶段 A 校验，再构造 frozen dataclass 和 tuple。非法内容抛 ConfigValidationError，含有脱敏 Issue；不同 PLC 身份不能解析为本地配置。

模型内字段使用 snake_case，线上 JSON 保持 camelCase。原始已验证报文保存为 wire_json，保留原有长度与数值表示；用于比较的 content_json 只包含 config，按子设备/点位 ID 排序、键排序，并统一整数等价表示。messageId、timestamp、configVersion 不影响业务内容比较。

因此修改消息 ID、JSON 排版、数组顺序或将 0 写为 0.0，不会导致同版内容冲突。更改点位地址、名称、缩放或 enabled 会形成不同内容。可选 unit 缺省与显式空串仍视为不同内容，不自动注入默认值。

## 3. Store API

```python
from pathlib import Path
from plcnext_iot.config.store import ConfigStore

with ConfigStore(Path("agent.db"), "PLC-01") as store:
    current = store.load_active()  # None 表示尚无已提交配置
    result = store.prepare(payload_bytes)
    # PREPARED: result.token 是候选凭证，尚未改变 current。
    # 只有后续执行协调器确认本地任务切换成功，才允许：
    # store.commit(result.token)
    # 切换失败时调用 store.fail(result.token)。
```

prepare 返回不可变 PrepareResult：status、active_config_version、token、code、issues。

| 情况 | 结果 |
|---|---|
| 新的合法版本，无其他候选 | PREPARED，返回随机 token，活动指针不变 |
| 同候选版本、同内容重复 | PREPARED，复用 token，可关联新消息 ID |
| 已提交活动版本同内容重复 | APPLIED，无 token；仅表示存储事实 |
| 低于当前活动版本 | REJECTED / STALE_VERSION |
| 已知版本不同内容，包括失败版本 | REJECTED / VERSION_CONFLICT |
| messageId 已被另一版本占用 | REJECTED / MESSAGE_ID_CONFLICT（本地错误） |
| 其他候选尚在准备，或存储配额用尽 | REJECTED / RESOURCE_LIMIT |
| 契约错误或身份不符 | REJECTED，包含原校验 Issue |

新候选准备期间，活动版本的合法重发仍可确认。一个 PLC 同时只允许一个待提交候选。未通过 prepare 的非法报文不进入快照/请求历史，未来诊断服务负责限流记录拒绝事件。

commit(token) 在单事务中更新候选状态、活动/前一指针和所有关联请求结果。同一个已提交 token 在该版本仍活动时可以重复提交；旧版本或失效 token 抛 InvalidCandidate。fail(token) 只把当前候选标记 FAILED 并撤销 token，不更改活动版本；同内容可重新准备并得到新 token。

**APPLIED 存储结果不能直接代表设备当前运行成功。** 首次激活前需执行协调器成功切换任务；重启恢复也需先完成设备任务重建，再发送线上 ACK。MESSAGE_ID_CONFLICT 等本地结果需由未来消息层转换为协议允许的错误，而非直接复制所有字段。

## 4. SQLite 结构与事务

| 表 | 职责 |
|---|---|
| metadata | 单行 gateway_id、active_version、previous_version |
| snapshots | version 主键、原始 payload、规范内容 hash、state、token |
| requests | message_id 主键、关联 version、PREPARED/APPLIED/FAILED/INTERRUPTED 结果 |

数据库通过 application_id=0x50494F54 和 user_version=1 标识。未知表库、未知应用 ID 或数据库版本拒绝打开，不执行自动覆盖升级。已有库的 gateway_id 与 Bootstrap 不符时拒绝使用。

使用外键、显式 BEGIN IMMEDIATE、WAL 和 synchronous=FULL。FULL 的 WAL 提交同步行为依据 [SQLite 官方 PRAGMA 说明](https://www.sqlite.org/pragma.html#pragma_synchronous)。这减少提交后掉电丢失窗口，但不能代替目标控制器存储介质及固件的断电验证。

发生写失败时事务回滚并抛脱敏 StoreError。Store 同步、同线程使用；现有 asyncio Agent 通过 StoreWorker 把创建、访问和关闭放在同一专用工作线程，避免阻塞事件循环或违反 sqlite3 连接线程约束。

## 5. 重启与所有权

打开库时先持有旁路 `.lock` 文件的 OS 锁。Windows 使用 msvcrt 字节锁，Linux 使用 flock；正常关闭和进程退出释放锁。锁文件保留，不删除重建。路径通过 resolve 规范化；部署必须使用同一本地数据目录，不能通过硬链接、网络共享或复制数据库绕开所有权。

启动恢复把所有 PREPARED 候选/请求改为 INTERRUPTED，并清除候选 token；load_active 只加载 COMMITTED 活动指针。因此即使准备 v11 后进程退出，已有 v10 仍是恢复源。相同 v11 内容可以重新下发准备；旧 token 不能继续提交。

已提交内容在读取时重新通过契约校验，并核对版本和业务内容 SHA-256。损坏或不一致时抛 StoreFormatError，保留原文件，不静默回退到其他版本或清空点表。hash 用于发现不一致，不是防篡改签名；认证及文件权限需由部署层提供。

previous_version 用于诊断，业务回滚仍通过更高版本发布旧内容。不可直接复制正在运行的 `.db` 文件作为完整备份；后续备份应使用 SQLite backup API 或停机后的完整一致副本。

## 6. 有界存储

默认最多保存 32 个配置版本、4096 个已接受请求身份、64 MiB 原始快照 payload。可由 ConfigStore 参数调低或调整；达到上限拒绝新增记录，不删除最后有效配置，同一已记录消息的重发仍可处理。

这些限制保护配置历史，不是遥测队列。payload 配额不等于 DB/WAL 物理文件大小；文件系统预留空间、日志及磁盘监控仍属部署工作。当前不自动清理配置历史：遥测补传按批次自带的 configVersion 校验，达到配额后应走维护策略，不能随意删除仍被历史数据引用的版本。

## 7. 运行演示与验证

项目根目录执行：

```powershell
./.venv/Scripts/python.exe -m unittest discover -s tests -v
./.venv/Scripts/python.exe -m tools.validate_contracts
./.venv/Scripts/python.exe -m tools.config_demo
```

演示使用系统临时目录，不触碰现场数据库。输出中 `deviceActivationPerformed=false`，依次验证准备 v10 不激活、提交存储 v10、准备 v11 后重开、恢复 v10。

测试使用真实 SQLite 和子进程 os._exit，覆盖 prepare 后退出、commit 后退出、写入中触发错误回滚、失败重试及 token 失效。Windows 开发环境已运行这些测试；真实 PLC 的断电、磁盘写满、Linux 文件锁及持续运行仍需真机验证。

执行协调器、MQTT 配置闭环、Modbus/OPC UA 采集和遥测补传均已实现。本说明只覆盖配置存储边界。
