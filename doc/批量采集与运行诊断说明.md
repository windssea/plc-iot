# 批量采集与运行诊断

本阶段在独立 IoT Agent 中实现批量 Modbus 读取、请求并发控制、子设备状态和 MQTT 心跳。OPC UA 子设备共用同一套 `device/status` 与 heartbeat 字段，采集方式见 [OPC UA 采集说明](OPC UA采集说明.md)。Hub 对接和 PLC 真机验收留待后续。

## 读取与并发

读取计划按区域、采集周期分组，按地址排序，只合并连续或重叠的点位，不跨未配置地址。寄存器每块最多 125 个，位区域每块最多 2000 位；32 位数据不会被拆成两个请求。每个点独立解码，单点解码失败不影响同块其他点。

合并请求返回 Illegal Address 时，退回已知点位范围，每轮最多追加 4 次请求；追加请求不重试。超时、连接失败或其他协议错误不触发拆分。响应长度不符按 BAD_PROTOCOL 处理。

同一 host（转小写）和 port 的请求串行，包括不同 Unit ID；全局默认最多 16 路。每个子设备仍拥有独立客户端。等待同端点不会占用全局名额，超过本次采集周期就跳过，取消和超时都会释放名额。主机别名与 IP 不做 DNS 等价归并，配置应统一端点写法。

轮询使用单调时钟，错过的周期不会追赶补发。`runner.skipped_polls` 记录跳过的块周期，`runtime.read_budget.skipped` 记录准入超时；目前可供本地代码诊断，未扩展到 v1 心跳字段。请求本身仍受连接/请求超时和重试次数限制。设备断线退避为 0.5 秒起、最多 30 秒，只在实际请求失败时增长。

## 设备状态

- DISABLED：PLC 总开关关闭、设备关闭或没有启用点位。
- CONNECTING：当前执行器尚无有效发布的采样。
- ONLINE：全部启用点位为 GOOD，且未超过各自 staleAfterMs。
- OFFLINE：所有点均为连接失败、超时或过期；轮询任务异常结束也按 OFFLINE 处理。
- DEGRADED：部分点异常，或存在协议/解码错误等其他情况。

`lastError` 使用固定错误代码，`lastGoodTimestamp` 为该执行器最近成功采样的墙钟时间。运行状态直接从执行器缓存读取，不依赖遥测队列能否及时上传。只修改报告参数时复用执行器及采样状态；修改连接或采集参数时重建执行器。

## 发布

启用 MQTT 后自动发布 `device/status` 和 `heartbeat`，均为 QoS 1、非 retained。独立任务每 0.5 秒检查设备状态，状态、错误或配置版本变化时发布；仅成功时间变化不会重复发布。断线重连后为新 session 重新发布当前状态。快速连续变化可能合并为最新状态，不作为事件审计日志。

连接后立即发送一次心跳，此后每 30 秒发送。心跳包含 sessionId、bootId、已提交配置版本、运行时间、设备状态、启用点位 GOOD/非 GOOD 数量，以及 Outbox 中 pending+dead 批次数、负载字节数和因容量不足拒收的批次数。bootId 与本次遥测流水共用。DISABLED 下点位计数为 0。配置应用中、关闭中、失败或提交版本未知时跳过心跳，避免伪报稳定状态。

平台侧可按 90 秒未收到心跳判断 Agent 失联；本阶段仅实现发布，尚未实现平台侧离线判定。MQTT `status` 仍表示连接状态，与子设备 ONLINE/OFFLINE 分开使用。

单元测试覆盖连续/重叠地址、空洞隔离、周期分组、读取上限、32 位边界、实际 TCP 合并报文、拆分预算、短响应、全局和端点并发、取消释放、退避恢复与状态契约。真实模拟器和 Mosquitto 验证两个子设备 ONLINE、断线 OFFLINE、恢复 ONLINE、心跳标识及既有持久补传闭环。

Linux 发布包、容器镜像和 WBM 开发包已提供。心跳 `agentVersion` 为 `0.2.0`。MQTT 入站丢弃不进入心跳；`queue` 只统计遥测 Outbox。真机性能和长时间运行需在目标 PLC 上另行验收。
