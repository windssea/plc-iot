## T03 实现

`PlatformTime` 归属于进程 `ProcessBootContext`，在采样与 MQTT 服务建立前创建；同进程配置服务重建保留该对象，身份、模式、时间基准或漂移依据改变需明确维护。MQTT 文件与 commissioning 记录均支持显式 `time` 对象；修改 Broker 凭据保留已有授时配置，不能静默退回系统时间。原配置默认 `SYSTEM_RTC`，状态明确未验证，不伪报平台同步。

平台模式不写操作系统时钟。m1 紧邻同步 SDK 提交，m4 在 Paho 网络回调入口采集，响应队列独立限 4 条/2048 B，并与普通接收轮转，避免授时洪泛挤掉 ACK。响应严格校验六字段回显、当前 session、非 retained、整数与派生安全边界，执行 P0/2 的 RTT、Hub 处理耗时和负 path 容差。首轮 30 秒/10 次，优先三个一致候选中最小路径；不足三个只在轮次结束选低 RTT 一致候选并提前复校。正常复校、失败退避、误差随漂移增长及一小时上限均用单调时间。

小偏差按 99.5%～100.5% 平滑；大偏差先 SUSPECT，有历史边界的确认回拨进入 MAINTENANCE。单调源倒退同样进入维护，不能清空锚点后靠重新授时绕过历史。`CAPTURE/ENQUEUE/CONTROL_SEND/SEND/ACK_APPLY` 分别处理：无效时间仍可本地采集，但未接纳样本不补时；已接纳历史保留；恢复后用当前令牌继续物化。新 session 必须复校，再按 heartbeat → config/get 成功提交 SDK 的顺序开放 DATA，不等待 PUBACK、APPLIED、新 GOOD 或第一条 STORED。

配置与真实 DATA ACK 接收在未授时时继续。retained DATA ACK 不应用；未授时产生的配置确认保留有界的请求关联及真实应用结果，恢复后使用当前控制时间重新编码，不能重复应用或伪造旧 APPLIED 状态。令牌包含 boot/时钟修订/连接修订及不足 2000 ms 的上下文期限，存储工作线程执行和实际 SDK 提交前复核。

本地 `/api/diagnostics/buffer` 和 pipeline stats 暴露模式、状态、逻辑 UTC、系统诊断时间、误差、同步年龄、时基、修订、控制资格、未知年龄/待维护批次数及缓存年龄；本轮没有新增远程诊断消息或宣称 Hub 已消费这些字段。

## T04 实现

Outbox 使用显式 SQLite v2；v1 运行文件不会启动时自动升级。必要元数据、备份和运维步骤见 [Outbox v2 时间元数据与迁移](../Outbox-v2时间元数据与迁移.md)。旧 payload、messageId、bootId、sequence、配置版本、timestamp、hash、attempts、计数与终态保持原值。旧 created 不作为可信年龄，旧 DEAD 不因 reason 相同就推定为本地过期。

新可信批次保存入队 UTC/误差/基准/boot/时钟修订及稳定本地顺序；在提交决策处刷新可信入队时间，并持久化已知历史时间下界。原批字节不改。当前时间无效、旧年龄未知或时基不可比时不按墙钟过期，数量/字节/物理磁盘配额始终生效。仅保守年龄下界达到七天且本轮确认机会结束，才事务转为带 `AGE_EXPIRED` 来源的终态。

同进程重连保留重试截止和 attempts。新进程不减旧 next_due；原已尝试批按当前单调时间重建 60 秒截止，未尝试批按总限速参与调度。首个实际尝试等待 30 秒，以后 60 秒。未来时间或其他时基的批次暂停发送并计入待维护；未知年龄本身不禁止恢复。合法 STORED 在当前授时失效时仍能删除匹配原字节哈希的批次；持久化 AGE_EXPIRED 来源支持重启后的迟到确认，未知/永久死信不复活，删除失败不报告释放成功。

存储串行工作线程统一处理 enqueue/reserve/expire/ACK。令牌检查是入队/预留事务的提交决策边界；此后失效不撤销已成功接纳历史，SQL/COMMIT 失败则仍由上游持有。时钟锁不跨 SQLite 或 fsync，慢存储不会卡住事件循环。
