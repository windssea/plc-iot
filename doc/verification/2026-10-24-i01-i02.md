## I01：采集出口与不可变事件

[Sample/SampleBuffer](../../src/plcnext_iot/points/samples.py) 保留旧诊断字段，新增 gatewayId、captureBootId/sampleSeq、config generation、真实 nominalPollDueMonoMs、completedMonoMs、名义计划原点、PHYSICAL_RESULT/QUALITY_STATE、timeValid/clockRevision/time generation/source。sampleSeq 与 DATA sequence 独立，由同一进程 [ProcessBootContext](../../src/plcnext_iot/core/boot.py) 分配，不用 UTC 去重，耗尽报错而不回绕。GOOD 只接纳有限 binary64 数值或 bool，其他质量的 value 必须为 null；所有已捕获对象冻结，原始 UTC 不回填。

[CaptureTime 接口](../../src/plcnext_iot/core/sample_time.py) 可注入，现有实际路径明确为 `SYSTEM_RTC_COMPAT`、timeValid=false，保留旧系统时钟兼容能力，不声称实现 MQTT 授时。测试用可控平台时间验证失效/恢复；未来 provider 需提供真实有效代际起点，采集器从其已有物理计划选取新网格起点，不把完成时刻反推成物理槽。已有历史保留捕获时的 UTC/配置/身份，失效期已选事件不能补时重新接纳。

[PointEvents](../../src/plcnext_iot/points/events.py) 在点启用时产生一次 UNKNOWN；按最近一次最终物理结果的完成单调时间判陈旧，从未取得结果时按启用计划起点计算。无结果达到阈值产生一次 STALE，时间为实际检测时刻；持续 BAD 不按最近 GOOD 的年龄改写为 STALE。新 GOOD/BAD 都结束无结果状态。独立、同事件循环的状态检测任务保证读取等待期间也能检测 STALE，检测间隔约 50 ms；实际检测时间随运行调度而变，不承诺设备实测延迟。

[Modbus 出口](../../src/plcnext_iot/devices/modbus.py) 从真实 block deadline 传递名义槽，一个最终 block 结果为 N 点各建一个事件，内部读取重试不重复建事件。预算不足/重连等待仅按点记录漏轮，不制造 BAD 物理样本。名义计划按整数毫秒核对漏槽，配置退休边界后的槽不计入旧配置。

[OPC UA 读取器](../../src/plcnext_iot/drivers/opcua.py) 与 [出口](../../src/plcnext_iot/devices/opcua.py) 改为按 pollIntervalMs 做计划读取；DataChange 通知不再追加物理事件，避免订阅通知与定时读取重复计样。常值仍通过实际读取维持活性。连接内部重试形成一次最终失败；没有读取结果的等待由 STALE/漏轮表示。这个行为变化按 P0/2 的实际物理槽执行，未在运行设备上切换。

采集前保留已发布配置令牌，等待预算后及结果提交前复核归属；在途旧版本结果分配旧身份并记 VERSION_DISCARD/undecidedLost 事实，不改挂到新版本。候选或已替换 runner 无发布权。相同配置重用/停止后重启以及同进程本地重载，保留采样代际、原计划与质量状态，不重复启动 UNKNOWN；真正配置/有效时间代际才重建相应采样基准。进程级状态只保留当前归属/版本的点视图和计划，不是持久历史。

入口有 4096 个事件的默认数量上限（可配置 1～10000）。满时拒绝新事件，不覆盖旧事件；事件身份在尝试前已分配，精确增加 captureOverflow/undecidedLost 并标记 accountingComplete=false，保留最后一次溢出身份。入口只允许每个身份按捕获顺序提交一次，重试不重新进入捕获入口。完整旁路明细、字节配额、统一 16 项 boot Total 和快照仍属 I03/I05。

## I02：事件入口选择与报告基准

[ReportEngine](../../src/plcnext_iot/reporting/engine.py) 在 accept 时对每个不可变事件决定一次资格；prepare 只物化已经接纳的事件，latest 仅作视图。规则覆盖所有模式的 FIRST/质量变化、严格 deadband/bool、按真实名义槽推进的 CYCLIC_DUE。周期游标在资格决定时推进，接纳失败也消费当前槽；QUALITY_STATE、提前变化不移动网格，不按组批/SQLite 完成时间选样。

比较基准取同一点/配置/有效时间代际中 sampleSeq 最新的 pending shadow 或 committed baseline。成功接纳才推进 shadow，成功本地 enqueue 才推进 committed；旧提交/重复提交不回退基准。相同配置在同一进程重载时保留已提交基准与报告网格，不能把重载当成新的 FIRST 或补发旧物理槽。

选择缓冲按事件数有界（默认 32768，包含已冻结但未完成 enqueue 的事件），拒绝接纳不推进基准，同一事件不重复计资格或损失。已接纳记录保持其原配置/时间身份，普通配置切换、停用或时间失效不清历史。其数量上限用于 I02 正确性边界；Python 实际 RAM 字节预算和工作量/吞吐门槛尚未通过 I03/C04 验收，不能据此宣称 32 MiB 等资源目标已满足。

同点多个应报事件分到不同 messageId，批内点唯一，按原 maxBatchPoints/131072 字节旧契约限制分批，不把 sampleSeq/kind 等内部字段加入 DATA。enqueue 返回 false 时保留原 ReportBatch/sequence/messageId/payload；再次 prepare 返回同一个冻结对象，避免重新编码。ACK 仍由原 Outbox 处理，不修改旧心跳或已持久批次语义。

[TelemetryPipeline](../../src/plcnext_iot/reporting/service.py) 接入新的采样身份/代际与提交边界，并提供本地阶段性入口/选择统计。这里的统计尚不是 I05 的统一 16 项 boot Total，部分仍随组件运行期重建；不能跨重载相减或当作完整采样对账。
