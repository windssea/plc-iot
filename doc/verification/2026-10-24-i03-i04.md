## I03：异步交接、配额及关闭

[TelemetryPipeline](../../src/plcnext_iot/reporting/service.py) 的入口消费/资格决定和持久提交是两个独立任务。入口不再逐条等待 `_flush()`；慢或忙的存储只阻塞提交任务，已接纳事件继续由 ReportEngine 持有，重复失败不增加事件终止损失。成功 enqueue 后才转移逻辑所有权并推进 committed baseline；事件关联的暂存副本不算第二个所有者。

[SampleBuffer](../../src/plcnext_iot/points/samples.py) 满时拒绝新身份；[ReportEngine](../../src/plcnext_iot/reporting/engine.py) 保留未提交事件、原冻结批次和基准引用。样本使用 slots，按对象实际大小及容器开销作保守记账；latest/committed baseline 持有的同一事件按引用计一次，冻结 payload 及样本引用另计。资格在首次入口决定，持久尝试不重新选样。

| 边界 | 当前硬限与行为 |
|---|---|
| 捕获 FIFO | 默认 4096 条、4 MiB，先触及任一上限就拒绝新事件，精确增加 undecidedLost/captureOverflow |
| 选择及冻结区 | 最多 32768 个未提交事件、32 MiB 保守记账；保留最多 2 MiB 物化余量，避免全满后无法组包；拒收不推进值/质量基准 |
| 冻结槽 | 最多 8 批，每类最多使用 7 槽，为另一类保留机会；每批最多 500 值/128 KiB，批内点唯一 |
| 遥测 StoreWorker | 单线程；运行中及等待任务合计最多 8 项、2 MiB；提交前准入，不能无限堆积 executor 队列 |
| 运行期 Outbox 元数据 | entries+staged 合计最多 10000 项、4 MiB；关联使用压缩 sampleSeq 数组，终态原因增长预留在配额内；无余量则保持上游 RAM 所有权 |
| SQLite payload | PENDING+DEAD 合计最多 10000 批、64 MiB，独立于其他限制；先触及的限制生效，不能保证任意尺寸记录都能达到 10000 批 |
| DEAD | 最多 128 批；按现有持久 rowid 顺序修剪，删除和 dead_pruned 在同一事务提交 |
| DB/WAL/SHM | 物理池 256 MiB；DB 页上限 128 MiB，写前保留 2 MiB 事务余量，至少保留 64 MiB 磁盘空闲；WAL 截断失败/外部读者占用时关闭写准入 |

[StoreWorker](../../src/plcnext_iot/core/storage_worker.py) 的任务计数/字节包括执行中的任务，取消调用者也要等线程实际完成才释放额度。配置库仍使用独立 worker，默认 4 MiB 工作额度容纳原 2 MiB 配置解析；遥测明确使用上表的 2 MiB。

[SQL 适配器](../../src/plcnext_iot/storage/batch_repository.py) 在打开前做磁盘预检，设置 max_page_count、wal_autocheckpoint、journal_size_limit，所有插入、发送预留、永久拒收、ACK 删除、死信修剪和旧计数写入均受物理池/空闲空间/检查点预检约束。无法写入时保留原所有权，ACK 删除失败不能提前计 STORED。这里已有生产保护代码及注入分支测试，**未用真实 SQLite/文件系统故障证明 256 MiB 上限**；该实测仍待 I06。逻辑配额、保守对象记账和 tracemalloc 结果均不等于整个 Python 进程 RSS 上限，配置、库、线程及 SQLite 自身开销仍需整体资源验收。

关闭沿用“先停 MQTT，再停生产者，再关闭遥测”的顺序。遥测关闭默认给出 5 秒排空期限，消费可处理入口，并在期限内提交；每次提交前复查期限。已明确未提交且没有数据库操作在途的剩余 RAM，记录 VOLATILE_RESTART/known_unsent，并保留事件明细出口；不伪装为持久成功。未完成的入口决策错误增加 undecidedLost/不完整标志。

如果期限到时线程仍在执行，close 返回 `TELEMETRY_CLOSE_UNSETTLED`、未结算事件数量和失败状态；该事务可能稍后提交，原 owner/关联继续保留，不能直接计 L 或 durable。清理任务在事务实际完成后继续转移/终止其余 RAM 并关闭存储；同进程重载在清理结束前拒绝启动第二个遥测 writer，OS 锁也保留至实际关闭。这个期限约束异步调用者，不承诺强制杀死挂住的 OS 磁盘线程或保证解释器进程在 5 秒退出。不存在设备断电持久承诺。

本地统计直接读取最近的 Outbox 缓存，避免健康发布等待慢提交；`outbox_stats_cached=true` 明示缓存性质。这不是 I05 的统一 16 项 Total 或跨线程原子诊断快照，不允许把当前 RAM 数与缓存的 Outbox 数相加来证明 E/S/P/L/I/U。

## I04：公平调度、退避和终态来源

[OutboxSession](../../src/plcnext_iot/storage/outbox_session.py) 由 ProcessBootContext 持有，同进程 MQTT 重连/本地设置重载保留 retry deadline、尝试类别、限速和事件关联。gateway 或存储目录发生变化且还有旧关联时拒绝切换；相同存储重新打开若发现应有记录消失/内容身份冲突，报错并保留原关联，不能静默清空。只有新进程才重建这些运行期状态。

当前发送仍处于明确的 `SYSTEM_RTC_COMPAT` 路径：MQTT 状态/config-get 控制恢复后进入 send_loop 时建立恢复水位；这不是新增 MQTT 授时门槛。水位取当时的 sampleSeq，已接纳 RAM/冻结/已提交批次为历史，之后接纳为新数据；从库恢复的批次全部为历史，attempts=0 的旧批也不能冒充新数据。再次恢复重新分类但不清退避/限速。新物化批不混合两类，原冻结批次整体保留原字节。

物化、提交交接和发送均为两类保留推进机会。双方有可执行项时按 1:1 交替；类内取最早可发送项，等待退避/ACK 的头项不阻塞后续可发送项。业务在途合计最多 8；单类最多占用 7，为另一类保留 1。若恢复状态已有 8 个历史在途，则等待真实释放/超时，首个释放信用优先供新数据参与公平调度，不额外越过八批上限。

首次尝试等待 STORED 30 秒，此后 60 秒，使用当前进程单调时钟；合法可重试 REJECTED 则从接收时重建 60 秒等待。白名单仅 UNKNOWN_CONFIG_VERSION、RESOURCE_LIMIT、STORAGE_ERROR；混有其他合法错误即永久隔离。持久 attempts 保留，旧 next_due 不作本轮截止点、不与 monotonic 相减；新进程对尝试过的旧批重建 60 秒等待，未尝试旧批按进程总限速推进。同进程重连不调用清零 due 的旧逻辑。

总发送尝试（含重试/明确 SDK 拒绝）按进程限制为每 250 ms 最多一次、任意滚动 1 秒最多 4 批/512 KiB；在实际 SDK 交接前再次记账，避免慢数据库或事件循环暂停造成追赶突发。PUBACK 等待是最多 8 个独立任务，业务 STORED 可先于 PUBACK 到达；PUBACK 不删除数据。[PahoConnection](../../src/plcnext_iot/messaging/transport.py) 区分 SDK 明确拒绝与接受后的等待失败：明确拒绝保留退避，但不把该次尝试当成已可能发送；连接丢失/慢 PUBACK 继续保守追踪原批次。

| ACK/终态情况 | 同运行期处理 |
|---|---|
| 有效 PENDING STORED | 删除事务成功后计确认并释放关联；重复 ACK 不重复计数 |
| 可重试拒收 | 保留 P 与原字节/身份，延后单调 deadline |
| 永久拒收 | DEAD，保存 PERMANENT_REJECT 来源及隔离事实；后续 STORED 作为冲突，不自动改判 |
| 本地年龄终止 | 曾可能发送则记录 uncertain，否则 known_unsent；活动 ACK 等待结束前保留确认机会 |
| 保留原记录/关联、曾发送、本地过期后 STORED | 删除成功后计 stored 与 late_stored，保留曾 uncertain 的历史事实；集合 U→S，不能把这些 Total 当互斥分组相加 |
| legacy DEAD/未发送/未知/已修剪 ID | 无法证明来源或发送资格时不凭 ACK 重建事件映射、不复活批次 |

ACK 路径不执行年龄扫描，当前时间失效也不会妨碍其结构/归属/状态核对。本轮七天判断仍用旧 created 与系统 RTC，是 **SYSTEM_RTC_COMPAT_UNVERIFIED**：不证明可信入队年龄、回拨后的过期正确性或 P0/2 授时恢复。可信时间迁移及完整边界矩阵仍属阶段 2。`telemetry.db` 保持 application_id 和 user_version=1、现有表/字段；未新增持久事件/时钟字段，不需要先行执行格式迁移，也没有实际打开或迁移库。跨进程事件关联和终态来源未知时明确不完整；I06 仍须单独回归原 payload 的真实持久性。

同运行期关联、terminal source、累计事实均有界；已确认/修剪后释放记录，事实计数不回退并在安全整数边界饱和。本地 `on_fact` 出口可接独立验收记录器，不消费业务 FIFO；拒写或异常标明 detailTruncated/accountingComplete=false。正式统一诊断与生产记录器接线属于 I05；本轮只为受测场景接入共同独立记录器作证据，不宣称线上完整取证已开启。
