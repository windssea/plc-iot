# 遥测报告、持久补传与独立接收端

启用 `--mqtt` 时，Agent 会将已采集的子设备样本按报告策略生成批次，先写入 `telemetry.db`，再发布 MQTT data。只有收到匹配的有效 data/ack=STORED 才确认交付并删除；死信修剪是另一种本地终止操作。配置库与遥测库的表格式保持不变。2026-10-24 当前代码及隔离结果见 [I01/I02](verification/2026-10-24-i01-i02.md)和 [I03/I04](verification/2026-10-24-i03-i04.md) 验证报告，运行 Agent 尚未切换；Hub v1 接收/取证已回归，Python 新改动尚未与其运行联调。

## 报告策略

| 策略 | 触发条件 |
|---|---|
| cyclic | 首值、质量变化或达到 reportIntervalMs |
| change | 首值、质量变化或相对最新已接纳基准的变化严格大于 deadband |
| change_or_cyclic | 上述变化条件或达到最长报告间隔 |

bool 比较是否改变，不进行数值死区计算。基准取同点/配置/有效代际中 sampleSeq 最新的已接纳 shadow 或已提交 baseline，接纳拒绝不推进基准。选择在不可变事件入口发生；已选事件不再按 latest 合并，质量变化不受死区抑制。同点的多个应报事件分到不同批次。

批次由 batchIntervalMs 驱动，每批最多 min(maxBatchPoints, 500) 个点，同时控制实际 UTF-8 大小不超过 128 KiB。一个批次仅包含一个 configVersion，一个点在批内只出现一次。周期报告保留原样本 timestamp，不把报告时刻伪装成新的采样时刻。

周期网格来自调度器的首个名义轮询槽，与组批/提交时间分开。物理事件服务最后一个到期槽，之前无结果的槽计 missedReportSlots；资格决定即推进游标，接纳拒绝也消费该槽。状态事件、提前变化不移动网格。ReportBatch.prepared_at 只记录物化时刻，不决定资格，也不进 MQTT/SQLite 新字段。enqueue 失败保留原冻结 payload、messageId 和 sequence，重试不重编码。

启用后尚无最终结果时创建一次 UNKNOWN；按最近最终物理结果（GOOD 或 BAD）的完成单调时间判 STALE，状态转换只创建一次，UTC 取检测时刻，不改写旧 GOOD。处理积压不会重写原事件时间，时间可信度与质量分开；单调时钟和事件身份不进入旧 MQTT 报文。

配置版本变化为新采样清理基准，已经接纳的易失事件和冻结批次保留原身份/所有权；已经持久化的旧批次继续按旧版本补传，禁用配置也不删除。尚未接纳的旧入口事件按 VERSION_DISCARD/undecidedLost 记录，不猜测其应报数量。入口消费与持久提交已拆为独立任务，慢/忙 SQLite 不同步阻塞资格决定，enqueue 失败仍为 P。I03 的数量/字节边界、有限关闭与易失范围见上方报告；实际存储故障和整体无损验收仍待完成。

## Outbox 的持久边界

独立数据库 `dataDirectory/telemetry.db` 使用 SQLite WAL、synchronous=FULL、OS 所有权锁、应用标识和版本检查。打开损坏、其他格式或其他 PLC 的库会报错，不能通过初始化覆盖。创建、读写和关闭均由单独 StoreWorker 线程执行。

批次保存不可变 payload、SHA-256、旧创建时间、尝试次数和兼容 next_due 字段。预留发送只更新尝试状态，不删除数据。运行期截止点改用进程单调时钟，忽略持久 next_due；重连/本地重载保留退避和限速，新进程为尝试过的旧批重建 60 秒等待，未尝试的旧批按总限速推进。messageId、bootId、sequence、configVersion、原采样时刻和 payload 均保持不变。新进程新报告使用新的 bootId。

| 限制 | 默认值和行为 |
|---|---|
| 总记录数量 | 10000 条，含待发和死信 |
| 总 payload 大小 | 64 MiB，含待发和死信 |
| 在途信用 | 合计最多 8 批；单类最多占 7，为另一类保留 1 |
| STORED 等待/重试 | 首次 30 秒，后续 60 秒；不限次数但受保留期限约束 |
| 发送速率 | 最多每秒 4 批，最多约 512 KiB/s payload |
| 历史与新接纳批次 | 每次发送恢复水位分类，双方有可发送项时 1:1；不是 attempts=0/重试分类，恢复库全部历史 |
| 待发保留 | SYSTEM_RTC_COMPAT 的旧 created 七天行为，活动 ACK 等待结束后才能本地过期；可信年龄迁移未实现 |
| 死信保留 | 最多 128 条，修剪旧死信并累计 dead_pruned |

入队超过 payload 数量/字节上限时拒绝新批次，累计 legacy dropped（拒绝入队次数），保留已有批次；报告层保留原冻结对象等待重试，不重新从 latest 取值，也不重复计事件损失。另有捕获区 4 MiB、选择/冻结区 32 MiB、工作队列 2 MiB、Outbox 运行期元数据 4 MiB 的分别准入边界。逻辑 payload 配额不等于磁盘上限；DB/WAL/SHM 物理池保护代码按 256 MiB 和 64 MiB 空闲预留执行，真实边界/故障验收仍待 I06，不以注入预检分支代替实盘证明。

仅本 PLC、已有且曾预留发送的消息可被 ACK 处理。STORED 在删除事务提交后确认；未知/重复 ACK 不复活数据。UNKNOWN_CONFIG_VERSION、RESOURCE_LIMIT、STORAGE_ERROR 保留待重试；混有其他合法错误则永久隔离，后续 STORED 标记冲突。同运行期保留原关联/本地过期来源且曾可能发送的 DEAD 可以接受迟到 STORED；未知来源 legacy DEAD、未发送或已修剪记录不凭 ACK 重建关联。ACK 不触发年龄扫描。SHA-256 用于检查存储内容一致性，不替代 Broker 身份认证和 Topic ACL。

## MQTT 与关闭

沿用原 MQTT 连接，订阅 `iot/v1/gateway/{gatewayId}/data/ack`，发布 `.../data`，两者均 QoS 1、非 retained。最多 8 个独立 PUBACK 等待任务，不串行阻塞后续批次和配置接收；应用 ACK 可能先于 PUBACK 完成。SDK 明确拒绝与接受后断线分开追踪，所有尝试计入进程总限速。应用 ACK 仍经过有界接收队列，丢 ACK 会重试，不能据此提前删除。

关闭先停止 MQTT 接收并结束当前配置处理，再停止采集，最后消费剩余样本并在默认 5 秒期限内提交。明确未提交的剩余 RAM 按易失/known_unsent 记录并返回失败；线程事务尚未完成则报 CLOSE_UNSETTLED，保留 owner/锁和后台清理，清理结束前拒绝同进程第二个 writer。调用期限不保证强杀 OS 线程或解释器退出。已经提交的末尾批次可能尚未发送，按既有恢复能力保留。没有 `--mqtt` 时保留原本地 sample 输出模式，不创建新的遥测库；已有遥测库不会被清空。

运行结束输出 telemetry_stopped，stats 包括 pending、dead、payload_bytes、dropped、dead_pruned、sample_dropped、version_discarded、cache_reset_points。配置切换清理缓存的点数和实际丢弃滞留样本数分开统计。报告任务错误触发失败事件并使 CLI 返回失败，已经提交的批次仍保留。

## 独立接收端

接收端工具 `tools.telemetry_receive` 使用自己的 SQLite 库，订阅 config/set 保存版本历史，并订阅 data。历史配置按内容校验，同版不同内容拒绝；缺少旧版本时返回 UNKNOWN_CONFIG_VERSION，允许通过 `--config` 补充历史文件后重试。

接收端校验消息契约、版本、子设备/点位归属、bool 类型、未来时间和批次过期，再将原报文和去重收据在一个事务内保存，提交后才发送 STORED。重复 messageId 且 payload 相同直接重新确认，不能重复入库；同 ID 不同字节内容返回 VERSION_CONFLICT。接收端落盘失败返回 STORAGE_ERROR，不发送 STORED。

这个接收端用于联调，保存完整批次，不实现最新值视图和实时告警。默认收据最多 10000 条/64 MiB、版本历史最多 32 份/64 MiB；不自动清理收据，达到容量返回 RESOURCE_LIMIT。历史数据归档、生产接收端扩容和告警投递属于后续工作。

## 运行方式

启动 Broker 和 Agent 的方式沿用 [MQTT 配置说明](MQTT配置闭环说明.md)。用独立终端运行接收端：

```powershell
./.venv/Scripts/python.exe -m tools.telemetry_receive --mqtt deploy/mqtt.example.json --gateway PLC-01 --database .local/receiver.db
```

如需补充历史配置，增加一个或多个 `--config .local/config-v10.json`。首次或重建 Broker 后，配置端仍需下发完整 retained 快照。

启动实际采集和上报：

```powershell
./.venv/Scripts/python.exe -m tools.agent --bootstrap deploy/bootstrap.example.json --mqtt deploy/mqtt.example.json --driver all
./.venv/Scripts/python.exe -m tools.mqtt_config_send --mqtt deploy/mqtt.example.json --gateway PLC-01 --config .local/config.json
```

`.local/config.json` 的地址和 Unit ID 应与模拟设备实际配置一致。Agent 与接收端均可用 Ctrl+C 停止，或以 `--run-seconds` 设置联调运行时长。

以下为既有版本的完整联调工具，会创建临时数据库/容器；本轮明确不执行。I01～I04 只运行受约束隔离入口，完整联调记录不能用于证明新源码已在设备通过。

```powershell
./.venv/Scripts/python.exe -m tools.telemetry_smoke --mock-project D:/work/code/PLCnext-mock-device --mock-python .local/mock-venv/Scripts/python.exe
```

独立模拟器虚拟环境的建立方式见 [Modbus 模拟采集说明](Modbus模拟采集说明.md)。脚本启动临时 Mosquitto 容器和模拟器真实 ModbusAdapter，使用临时 Agent/接收端数据库；不修改原模拟器状态。

验收读取两台子设备的四个点，检查 pressure=12.5、voltage=230 和 bool 值。接收端先落盘但不 ACK，确认 Agent 仍保留批次；随后重启 Agent、切换停用 v11，验证原 v10 批次按原字节补传、接收端去重以及确认删除。最后执行真实 Agent/接收端 CLI，验证 MQTT 下发 v12 后的采集与上报。

批量 Modbus 读取、设备状态、心跳、容器镜像和 WBM 开发包已在后续阶段落地。Hub 对接尚未开始。模拟器验收不能代替 PLC 真机断电、磁盘耗尽、长期运行及吞吐验证；可靠性承诺从成功写入 Outbox 开始，而非现场每一次采样开始。OPC UA 点值走同一条报告和补传路径。
